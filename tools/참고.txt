회사 개별 내용을 수정할때

`companies.json`에서 고치시면 됩니다. 다만 고친 뒤에 `rebuild`를 한 번 실행해야 페이지에 반영됩니다. `companies.json`만 고쳐서는 페이지가 바뀌지 않습니다.

**수정 순서**
1. `tools/companies.json`을 메모장이나 VS Code로 엽니다. `Ctrl+F`로 회사 이름을 검색하면 그 업체의 항목이 나옵니다. 큰따옴표와 쉼표는 지우지 말고 따옴표 안의 값만 고치세요. 저장할 때 인코딩은 UTF-8로 유지해야 한글이 깨지지 않습니다.
2. 저장소 맨 위에서 아래를 실행합니다.
   ```
   python tools/build_possible.py rebuild
   ```
3. GitHub Desktop에서 `Commit`과 `Push`를 합니다.
4. 필요하면 서치어드바이저에서 그 업체 주소를 수집 요청해서, 네이버가 바뀐 내용을 빨리 읽게 하세요.

**하지 말아야 할 것**
- **업체 폴더의 `index.html`을 직접 고치지 마세요.** 다음 `rebuild`나 다른 수정 때 덮어써져서 고친 내용이 사라집니다.
- **`기업명`은 고치지 마세요.** 기업명이 곧 폴더 이름이자 주소입니다. 이름을 바꾸면 새 업체로 인식돼 새 폴더가 만들어지고, 옛 폴더와 주소는 그대로 남습니다. 상호가 바뀌는 경우는 따로 처리 방법을 알려 드릴 테니 말씀해 주세요.

**알아둘 점**
- 값을 고칠 때 설립일은 `1986년 3월 25일` 형식이어야 하고, 주소 앞 지역명이 줄임말이어도 `rebuild`가 전체 표기로 바꿔 줍니다. 형식이 틀리면 `rebuild`가 이유를 알려주고 멈춥니다. 고친 직후에 `python tools/build_possible.py check`로 먼저 점검해도 됩니다.
- `rebuild`는 모든 페이지를 다시 만들기 때문에, 고치지 않은 페이지의 내용은 그대로여도 사이트맵에서 업체 페이지 전체의 `lastmod`가 오늘 날짜로 바뀝니다. GitHub Desktop의 `Changes`에는 실제로 바뀐 파일만 뜹니다. 한 업체만 고치는 일이 잦다면 그 업체만 갱신되게 만드는 옵션을 추가해 드릴 수 있습니다.
- 썸네일은 이름만 들어가는 이미지라 `rebuild`가 다시 만들지 않습니다. 기업명을 안 바꾸는 한 신경 쓰지 않으셔도 됩니다.

고치려는 항목이 상호 변경이나 업체 삭제처럼 값 수정이 아닌 경우라면, 그 경우에 맞는 절차를 따로 정리해 드리겠습니다.
